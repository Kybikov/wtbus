# Спільний рушій та збережені види сутностей

Клієнти, бронювання, команда, маршрути, автопарк, індивідуальні заявки, блокування дат, рейси та каси водіїв використовують `EntityDataView` і один `EntityViewToolbar`. Зліва — стандартний вид, збережені види та створення нового. Справа — режим відображення, фільтри й колонки. Масові дії з'являються окремо тільки після вибору записів. Таблиця, список, галерея, канбан та групування за датою підтримують чекбокси; контекстне меню має ті самі дії та відкриття деталей. Вибір автоматично очищується від записів, які зникли з результатів пошуку. Тулбар має спільну панель `workspace-panel` із топбаром та метриками: однакові зовнішні краї, фон, рамка та радіус. Нейтральні кнопки й обидва варіанти пошуку використовують стилі з `lib/admin-ui.ts`; основна дія зберігає акцентний колір. Бокові відступи задає тільки зовнішній контейнер робочого екрану, не кожна область окремо.

Вид зберігає режим, видимі колонки, фільтри та метрики в PostgreSQL (`entity_views`). Доступні таблиця, список і галерея; команда та бронювання також мають канбан, а бронювання, заявки, рейси та блокування — групування за датою. Автопарк, заявки та рейси також мають канбан. Рейси мають окремий режим «Расписание»: збережено тижневу навігацію, вільні автомобілі та перетягування із серверною перевіркою конфліктів. Локальний текстовий пошук залишається незалежним від виду. Фільтри клієнтів і команди працюють зі списком, завантаженим сторінкою; статус та дата бронювання передаються серверу.

- Приватний вид доступний лише його автору, включно з перевірками читання та видалення за ID.
- Спільний вид бачать працівники компанії з доступом до відповідної колекції. Змінювати його може автор, власник, адміністратор або розробник. Інші можуть створити власну копію через «Создать вид».
- Колекції команди та кас водіїв доступні лише власнику, адміністратору та розробнику. Види завжди ізольовані за компанією.
- Назви унікальні без урахування регістру: для спільних видів у колекції компанії, для приватних — у колекції автора. Ліміт — 200 видів на колекцію компанії.
- Редагування перевіряє версію запису. При конфлікті слід оновити список або створити копію; чужі зміни не перезаписуються автоматично.
- Видалення виду не змінює клієнтів, бронювання чи співробітників. При видаленні автора спільний вид зберігається, приватний більше не доступний.

У `localStorage` зберігається тільки ID останнього вибраного виду з ключем компанії, членства та колекції. Самі настройки завантажуються з API. Відсутні колонки й режими після оновлень безпечно замінюються доступними. Метрики видалених полів або недоступних операцій пропускаються.

## Нижня панель метрик

`EntityMetricsBar` відображається в окремій нижній області `AppShell`: записи прокручуються, а панель залишається доступною в усіх режимах і на телефоні. Лічильники над колекцією прибрано. «Всего» показує загальну кількість результатів серверного пошуку; «Показано» з'являється, коли відображено менше, а «Выбрано» — після вибору записів.

Через «+ Метрика» можна додати до 12 показників за полями, включно з прихованими колонками та додатковими полями клієнта. Для всіх типів доступні заповнені, порожні й унікальні значення; для статусів та логічних полів — кількість за конкретним значенням; для чисел і грошей — сума, середнє, мінімум та максимум. `0` і `false` вважаються заповненими. Грошові розрахунки використовують суми в мінімальних одиницях і показують кожну валюту окремо.

Додані метрики рахуються за показаними записами після фільтрів виду, а не за всією базою. Якщо сервер обмежив завантаження, пояснення через кнопку «i» вказує завантажену та загальну кількість. Порядок і набір метрик зберігаються разом із приватним або спільним видом; меню показника дозволяє перемістити чи видалити його. Старі види без `metrics` відкриваються з порожнім набором. Додавання метрик не потребує нової міграції: конфігурація залишається JSONB.

## Міграція та перевірки

Перед випуском Go API застосуйте `backend/migrations/000029_entity_views.up.sql` після резервної копії та перевірки її відновлення. Міграція додає лише нову таблицю та індекси. Відкат видаляє збережені види, тому його застосовують тільки після відкату коду та окремого збереження цієї таблиці.

`npm test`, `npm run typecheck`, `npm run lint`, `npm run build`, `go test ./...`, `go vet ./...`. Інтеграційна перевірка CRUD, приватності, ізоляції компаній та конфліктів: задайте `ENTITY_VIEWS_TEST_DATABASE_URL` на одноразову мігровану тестову БД і виконайте `go test ./cmd/api -run TestEntityView -v` з `backend`.

## Деталі запису

Вісім основних колекцій мають адреси `/{колекція}/{UUID}`. Деталі відкриваються з назви рядка, картки, меню дій, контекстного меню та результатів глобального пошуку. Сторінка використовує адаптований React Bits Pro `app-dialog-6` із shadcn Card: дані, пов’язані записи та зареєстрована історія дій завжди видимі окремими блоками на одній сторінці без вкладок. Дані займають усю ширину; зв’язки й історія розміщені поруч на великому екрані та один під одним на телефоні. Таймлайн історії адаптований із React Bits Pro `billing-8`, без демонстраційних даних та дій. Можна скопіювати ID, оновити запис і перейти до колекції з її чинними формами редагування. GPS-точка автомобіля має посилання на Google Maps.

API деталей завантажує конкретний запис за ID незалежно від ліміту списку. Запит запису, зв’язків та історії обмежений компанією сесії. Водії не мають доступу; деталі співробітника доступні лише власнику, адміністратору й розробнику. Паролі, токени оплати, конфігурація компанії та внутрішні payload провайдерів не повертаються. Історія показує лише вже зареєстровані `activity_events`; вона не відновлює незареєстровані минулі зміни. Зв’язки обмежені 20 останніми записами, історія — 30 діями.

Перед випуском цього розширення застосуйте `000030_more_entity_views.up.sql` після резервної копії та перевіреного відновлення. Вона розширює допустимі колекції без зміни даних видів. Відкат не дозволений, доки існують види нових колекцій: спочатку їх потрібно експортувати. Додаткові інтеграційні перевірки деталей: `go test ./cmd/api -run TestEntityDetails -v` з одноразовою `ENTITY_VIEWS_TEST_DATABASE_URL`.
## Універсальні дії топбара

На телефоні та планшеті дії конкретної сторінки згортаються в меню «Действия страницы», а спільні іконки залишаються видимими; на вузьких екранах до 380 px зменшуються кнопки й відступи сепараторів. У всій адмінці перед оновленням розміщені спільне меню «+», вертикальний сепаратор, імпорт та експорт. Меню створення відкриває чинні форми клієнта, бронювання, рейсу, маршруту, автомобіля, блокування дат і співробітника. Вибір на іншій сторінці переходить до потрібної колекції та одноразово відкриває форму; параметр `create` прибирається, тому оновлення сторінки не відкриває її повторно. Автомобілі й співробітники доступні для створення лише власнику, адміністратору й розробнику. Водії не отримують дії створення, імпорту та експорту CRM.

Імпорт клієнтів приймає CSV/XLSX через наявний серверний обробник і показує результат та помилки рядків. Експорт клієнтів у XLSX вивантажує всю базу компанії. «Текущий вид · CSV» експортує завантажені результати поточного виду після пошуку та фільтрів, із видимими колонками; меню позначає часткове завантаження, якщо відомий серверний ліміт. Експорт доступний у всіх режимах колекції. Порожні та завантажувані види не експортуються. CSV містить UTF-8 BOM, екранує лапки й переноси та захищає текстові клітинки від виконання формул у табличному редакторі.

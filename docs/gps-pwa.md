# GPS водія: робота та перевірка

GPS надходить лише з PWA `/driver`. Telegram не є другим джерелом координат.

## Поточна поведінка

- Водій запускає GPS явною дією. У браузерах із Web Locks лише одне вікно цього сайту може утримувати GPS-спостереження. Ручне передавання точки доступне окремо.
- Під час автоматичної передачі нова точка записується не частіше ніж раз на 25 секунд, навіть без мережі. Ручна точка не обмежена цим інтервалом. Точки з похибкою понад 200 м не використовуються; екран пояснює причину.
- Кожна точка спочатку потрапляє в IndexedDB, у простір конкретної компанії та членства водія. Межа — 5000 точок. При переповненні/помилці сховища GPS зупиняється з поясненням; старі точки не витісняються мовчки.
- Відправник видаляє лише підтверджені ідентифікатори. Один прохід обробляє до 50 точок послідовно; наступний запускається таймером. Це не пакетний HTTP API.
- При втраті мережі, таймауті, HTTP 429 або 5xx точка залишається в черзі. Повторні спроби мають затримку від 2 до 60 секунд. Відновлення перевіряється і без події `online`.
- Сервер забезпечує ідемпотентність за `tenant_id + client_point_id` і перевіряє, що повтор не підміняє водія, автомобіль, рейс, час або координати. `membershipId` запобігає відправленню старої черги під іншою сесією.
- При 401/403 збір зупиняється, черга зберігається. Відхилені без можливості повтору та старші за 48 годин точки прибираються з видимим повідомленням. Старе localStorage-сховище v1 не надсилається автоматично, бо не містить ідентичності власника; його дані залишаються на пристрої.
- Перед завершенням рейсу GPS зупиняється і виконується обмежена за часом спроба доставки. Якщо черга ще не порожня, завершення слід повторити після відновлення зв'язку. Зміна призначення також прибирає попереднє GPS-спостереження.
- PWA запитує Screen Wake Lock і повторно запитує його після повернення на екран. Браузер/ОС може відмовити; водій бачить стан.
- Диспетчерський екран оновлюється кожні 30 секунд, коли видимий. GPS старший за 2 хвилини позначається як застарілий; масштаб карти після початкового позиціонування не скидається.

## Межі PWA

Відкритий екран і дозвіл геолокації необхідні для передбачуваної роботи. Заблокований екран, згорнута PWA, завершення процесу ОС або розряджений телефон можуть зупинити отримання координат. Wake Lock не дає дозволу на фоновий GPS. Під час рейсу рекомендовані відкрита PWA, автомобільний тримач і заряджання.

Черга переживає перезавантаження сторінки. Проте холодне відкриття без інтернету показує автономну `/offline.html`: цей екран не збирає GPS. Після повернення мережі потрібно відкрити `/driver` та підтвердити сесію. Автоматичне відновлення збору після повного закриття не вмикається без дії водія.

## Оновлення сервера

Спочатку застосувати міграцію `000025_gps_delivery_ids`, потім оновити API та вебзастосунок. Старі клієнти без `clientPointId` залишаються сумісними, але не мають нового захисту від дублів. У Coolify міграції запускаються окремо через профіль `maintenance`; штатний запуск API їх не застосовує. Перед міграцією виконати резервне копіювання згідно з README.

## Автоматичні перевірки

```powershell
npm test
npm run typecheck
npm run lint
npm run build
```

У `backend`: `go test ./...`, `go test -race ./...`, `go vet ./...`.

Інтеграційні GPS-тести використовують тільки окрему локальну базу з усіма міграціями. Перед запуском установити `GPS_TEST_DATABASE_URL`, потім виконати `go test ./cmd/api -run TestGPS -v`. Тести створюють власного tenant-а і прибирають свої рядки. Вони перевіряють паралельні повтори, незмінність точки, належність водію, правильний рейс спільного автобуса, сумісність зі старим клієнтом і відхилення точок завершеного рейсу.

У браузері з підставленим GPS перевірено: точність, старт/стоп, втрату дозволу, офлайн-запис, відновлення мережі, 503, перезавантаження з чергою та друге вікно. Це перевірка логіки, а не фізичного GPS телефона.

## Приймання на реальному телефоні

На фактичних Android/iPhone водіїв перевірити встановлену PWA: 30–60 хвилин руху, стоянку, втрату мережі, повернення з навігатора, відкликання дозволу, енергозбереження, блокування/розблокування екрана та завершення рейсу. Порівняти час і точність на телефоні та карті диспетчера. Поновлення GPS після блокування не вважати гарантованим до перевірки конкретної ОС/браузера.


## Планова довжина та прогрес рейсу

`routes.distance_km` — вручну задана планова довжина маршруту. Міграція 38 залишила для старих маршрутів значення 0 («не задано»). Для фіксованої ціни довжина необов’язкова; для тарифу за кілометр API вимагає додатну довжину та хоча б один тариф класу авто. Ціна розраховується за плановою довжиною, а не за поточним GPS-пробігом. У картці маршруту довжина редагується зі збереженням при втраті фокуса.

У деталях рейсу блок «Дорога и GPS» дозволяє вибрати місце відправлення й прибуття за назвою або адресою, вставити посилання Google Maps, повторно вибрати використане місце компанії або поставити точку на карті. Назва та координати зберігаються разом, відразу після вибору через послідовну чергу; текст пошуку — тимчасова чернетка. Між точками сервер будує автомобільну дорогу OSRM з повною GeoJSON-геометрією; невдалий розрахунок не затирає попередню дорогу. Нова одиночна поїздка після створення відкриває деталі для налаштування місць.

Пошук адрес використовує сумісний із Photon сервіс `GEOCODING_SERVICE_URL` (початково `https://photon.komoot.io/api/`). Запит запускається лише кнопкою пошуку або Enter; введення тексту тільки фільтрує «Ваши места». Сервер ідентифікує застосунок, обмежує звернення до одного за секунду в одному процесі та кешує до 256 результатів на 24 години. Публічний demo-сервіс допускає помірне використання без гарантії доступності; для навантаження або кількох реплік потрібен власний чи договірний endpoint. Джерело та формат: [Photon](https://github.com/komoot/photon). Підказки не надсилають живі координати водія. Список використаних місць читається тільки з маршрутів і рейсів поточної компанії. Назви зберігаються в JSON `navigation`, нова міграція не потрібна.

Google Maps: підтримуються адреси, `q`/`query` з адресою або координатами, вибрані місця з `!3d…!4d…`, короткі `maps.app.goo.gl` та `goo.gl/maps` через перевірені перенаправлення. Координати центру перегляду `@…` не підміняють вибране місце; неоднозначна ссылка на кілька точок пропонує вставити адресу. Кожен redirect перевіряє явний список HTTPS-доменів Google Maps, без довільних портів, облікових даних чи доступу до внутрішніх адрес. Окремого блоку посилань під картою немає; компактна атрибуція та посилання про помилки залишені всередині карти відповідно до умов її постачальників.

Перший рейс із повною дорогою передає її пов’язаному маршруту, якщо той ще не має власних точок. У деталях маршруту обидві точки можна змінити незалежно. Наступні рейси беруть ці значення як початкові; зміни маршруту не переписують уже створені рейси. Зміна пов’язаного маршруту в рейсі підставляє його точки. Індивідуальний рейс без шаблону також має власну дорогу. Міграція 48 реалізує копіювання на рівні бази з перевіркою компанії.

В «Обзоре» відсоток — позиція останнього GPS саме поточного рейсу на збереженій дорозі: відстань вздовж геометрії до проєкції координати / повна довжина геометрії. Це не сума всіх кілометрів, які реально наїздило авто, і не ETA. Стоянка не збільшує відсоток; повернення назад зменшує його. Сигнал старший 2 хвилин, точність понад 200 м або відсутня, відхилення від дороги понад max(75 м, точність + 30 м) приховують відсоток. На петлях/перетинах, де кілька близьких сегментів віддалені вздовж дороги більш ніж на 500 м, система показує «Уточняем позицию», без довільного стрибка на іншу ділянку. Час рейсу показується окремо й не рухає машинку.

Сервер передає зовнішньому маршрутизатору лише вибрані кінцеві точки; живі координати водія прив’язуються локально. `ROUTING_SERVICE_URL` задає сумісний OSRM-сервер; початкове значення — `https://router.project-osrm.org`. Публічний сервер працює без гарантії доступності; запити обмежені до одного на секунду в одному процесі, геометрія зберігається й не запитується при кожному GPS-оновленні. Для кількох реплік/значного навантаження потрібен власний чи договірний сервер. Побудова: 12 с HTTP timeout, загальний бюджет 15 с, відповідь до 8 MiB/100000 точок, перевірка координат, довжини та близькості кінців до вибраних точок. Автомобільний профіль не перевіряє габарити автобуса та автобусні обмеження; диспетчер перевіряє дорогу на карті.

Перед випуском застосувати `000048_route_navigation` після резервної копії та перевірки відновлення. Тарифна `distance_km` і погоджена ціна залишаються незалежними від геометричної довжини. Політики: [OSRM API](https://project-osrm.org/docs/v26.6.1/http), [публічний сервер](https://routing.openstreetmap.de/about.html), [тайли OSM](https://operations.osmfoundation.org/policies/tiles/).

### Випуск 1 листопада 2026

Перед міграцією створено `/var/lib/postgresql/data/vivat-before-gps-v48-20261101.dump`; `pg_restore --exit-on-error` успішно відновив її в окрему базу `vivat_gps_restore_v47_20261101`. Міграцію виконано однією транзакцією з перевіркою чистої версії 47 та `lock_timeout=5s`; після commit підтверджено версію 48 без dirty і обидві колонки `navigation`. Робочі записи для тестів не створювали й не видаляли.

Для тайлів карти явно задано `referrerPolicy: "origin"`: OSM отримує адресу походження сайту, не шлях запису. Це виконує вимогу постачальника попри загальний `no-referrer` застосунку та усуває зображення «Access blocked». Зміна стосується тільки зображень карти. Обидві карти використовують канонічний HTTPS endpoint тайлів OSM.

# Vivat Bus — аудит готовності, 13.09.2026

Цей аудит відображає фактичний стан коду та розгорнутого середовища `vivat.wtmelon.store`. Уточнення власника продукту мають пріоритет над початковим ТЗ у PDF.

## Перевірено й працює

- Авторизація без ручного введення компанії, вибір компанії для користувачів із кількома членствами, серверні сесії та ролі `owner`, `admin`, `dispatcher`, `driver`.
- Ізоляція даних компаній у PostgreSQL, Redis для стану Telegram-сценарію та оперативних подій.
- Регулярні маршрути, одиничні та повторювані рейси, недоступність, перевірка конфліктів автобуса й водія.
- Ціна маршруту та перевизначення для рейсу, режими «за пасажира» й «за бронювання», валюти UAH та EUR.
- Автопарк, водії, клієнти, додаткові поля, імпорт та експорт клієнтів Excel/CSV.
- Бронювання без вибору місця: ПІБ пасажира, телефон, дата народження, кількість пасажирів і статуси.
- Оплата при посадці, IBAN тільки для UAH, 30-хвилинний резерв, QR НБУ з сумою та призначенням, ручне підтвердження переказу менеджером.
- Реєстр заявок на індивідуальний трансфер і повідомлення клієнта про зміну статусу.
- Фінансова зведеність, готівка водія, витрати, PWA та передавання GPS координат із телефону водія.
- SaaS-основа: tenant-модель, брендинг компанії, особисті налаштування інтерфейсу, API керування підпискою для майбутньої інтеграції з центральним бекендом.
- Docker Compose / Coolify deployment, HTTPS, health checks, приватна мережа PostgreSQL і Redis.

## Виправлено під час аудиту

- Бот більше не вимагає знати й вручну вводити назви міст: доступні напрямки показуються inline-кнопками.
- Додано окремий список найближчих доступних рейсів у боті.
- Назву й навігацію місяця в календарі перенесено над днями тижня.
- Бронювання можна почати без збереженого стану пошуку — напрямок безпечно завантажується за обраним рейсом.
- Валюта регулярного рейсу тепер береться з маршруту, а не з базової валюти компанії.
- Власник може встановити тимчасовий пароль співробітнику; активні сесії після цього відкликаються, примусової зміни пароля немає.
- У production додано 19 майбутніх тестових рейсів, UAH/EUR сценарії, тестового клієнта та готівкове бронювання.

## Блокує повну перевірку оплати

- У налаштуваннях компанії немає реальних реквізитів: назви отримувача, українського IBAN, ЄДРПОУ/ІПН та назви банку. До їх введення IBAN-переказ навмисно вимкнений, готівкова оплата працює.
- Без еквайрингу або банківського/open-banking API автоматичне підтвердження надходження неможливе. Поточний погоджений сценарій — ручне підтвердження менеджером.
- Банки не публікують єдиний гарантований зовнішній deep-link для передзаповненого IBAN-платежу. Надійний міжбанківський механізм — QR за стандартом НБУ; конкретні приватні URL-схеми не слід використовувати без офіційної документації банку.

## Потребує ручного приймального тесту

- Повний Telegram-сценарій реальним акаунтом: надання контакту, дата народження, кілька пасажирів, UAH QR, EUR готівка, «Мої поїздки», скасування та індивідуальна заявка.
- Відкриття QR НБУ у фактичних версіях monobank, Приват24, ПУМБ та А-Банк на Android/iOS.
- GPS у встановленій PWA на реальному телефоні з дозволом геолокації, блокуванням екрана та нестабільним інтернетом.
- Візуальна перевірка всіх сторінок на desktop/tablet/mobile. Частина форм досі використовує нативні `input` із ручними класами; їх потрібно послідовно перевести на спільні shadcn-компоненти під час UI-приймання.

# Пошук і роль розробника

На сторінках колекцій топбар містить одне поле локального пошуку шириною 11rem. Воно має очищення та кнопку відкриття глобального пошуку. На телефоні поле відкривається через іконку пошуку; використовуються ті самі стилі та дії. На сторінках без локального пошуку показується глобальний пошук.

`Ctrl+K` / `Cmd+K` відкриває shadcn Command із фокусом у полі. Фізична клавіша K працює також в українській розкладці. Стрілки змінюють вибраний результат, Enter відкриває його, Escape закриває меню. Текст запиту й вибраний пункт мають окремий стан. Розділи шукаються відразу, клієнти та бронювання — від двох символів із затримкою 220ms. Новий запит прибирає старі результати й скасовує попередній запит.

API бронювань шукає ID, контакт клієнта, фактичного пасажира, всіх пасажирів групи та міста маршруту. Результат клієнта відкриває його телефон як фільтр `/customers?q=…`; бронювання відкривається за точним ID `/bookings?q=…`. Локальні серверні пошуки скасовують попереднє завантаження, щоб повільна відповідь не замінювала нові результати.

Міграція `000028_developer_role` додає роль `developer`, яка відображається як «Разработчик». Вона має доступ до всіх дозволів API та розділів своєї компанії, включно з командою, фінансами й налаштуваннями. Перевірка компанії, захист системної автоматизації, поточного користувача від видалення й останнього власника залишаються чинними. Призначати або змінювати роль розробника може лише розробник; перший доступ призначається через контрольоване адміністрування БД. Сесії читають роль із чинного членства при кожному запиті.

Початкове налаштування власника при запуску API зберігає вже призначену роль розробника. Перед production-міграцією створити резервну копію та перевірити відновлення в окремій БД. Відкат переводить розробників у `admin`; невикористане значення enum залишається, оскільки PostgreSQL не підтримує його безпечне видалення на місці.

# Мобільна навігація

Оновлення від 01.11.2026.

Повне основне меню відкривається зліва зверху. Аватар відкриває праве меню з кількістю непрочитаних сповіщень, керуванням поточною сторінкою, підрозділами статистики/налаштувань, особистими налаштуваннями та вибором нижніх вкладок. Мобільні «Ещё», окремий дзвіночок і меню з трьома крапками прибрані з верхньої/нижньої навігації. Десктопне керування збережене.

Нижня панель має «+», вибрані розділи без обмеження їх кількості і окрему круглу кнопку глобального пошуку. Крайні дії відділені вертикальними розділювачами. Створення показує тільки дозволені ролі цілі, використовує поточний обробник форми або перехід `?create=1`; автоматичної відправки форми немає. Пошук охоплює доступні розділи, клієнтів та бронювання, зберігає можливість застосувати запит до поточної сторінки.

Вибір вкладок одразу зберігається в localStorage з ключем `vivat:dock:<tenantSlug>:<membershipId>`. Налаштування діє в цьому браузері, окремо для компанії та членства; серверна синхронізація цих нових налаштувань не додавалася. Під час читання збережені адреси повторно перевіряються за поточною роллю, дублікати й сторонні адреси відкидаються. Порожній/пошкоджений вибір повертає стандартні вкладки ролі. Помилка запису відображається користувачу.

Керування видами списків переноситься в праве меню через портал. Праве меню зберігається змонтованим, щоб його закриття не скидало стан панелі видів. Наявний портал банера незбережених змін у body лишається незалежним від видимості меню. Зміни записів та чернетки виду зберігають попередні правила.

На телефоні період обирається в одному календарі, на десктопі — у двох. Календар показується перед швидкими періодами, вікно прокручується вертикально. Початкове виділення, межі дат, вибір місяця/року та готові періоди збережено.

Оновлення жестом обробляється тільки у верхній точці основної області прокручування, одним пальцем, при переважно вертикальному русі вниз. Свайпи вбік, прокручування нижче початку, multitouch та взаємодії з кнопками/полями не запускають оновлення. Поріг — 64 CSS px після опору жесту; повторне оновлення під час активного запиту відхиляється. Віджет крутиться під час оновлення й зникає після завершення. Помилка, яку повернув обробник, відображається у віджеті; помилки, які обробляє сама сторінка, залишаються у її звичайному повідомленні.

## React Bits

Усі три запитані Sorbet-джерела отримані з ліцензованого реєстру React Bits Pro зі статусом 200: `mobile-2-sorbet`, `mobile-3-sorbet`, `mobile-5-sorbet`. Вихідні файли прочитані перед адаптацією. Застосовано spring-стек і поворот «+» з Mobile 2, плаваючу панель/пошук і активну вкладку з Mobile 3, згруповані прокручувані рядки та округлення списків із Mobile 5. Демо-дані, власні шрифти й кольори Sorbet не замінюють систему Vivat. Шар діалогів/focus trap/Escape залишається на спільних shadcn/Base UI примітивах; анімація поважає reduced motion.

Булеві перемикачі використовують наявний [Squish Switch](https://reactbits.dev/c/micro/squish-switch) через `DeliverySwitch`, включно з темою та налаштуванням нижніх вкладок. Чекбокси вибору записів і збережених видів не перетворювалися на перемикачі.

Ключ з `.env.local.txt` перенесено до ігнорованого `.env.local`; у вихідні файли або документацію ключ не записувався. Початкові ліцензовані JSON/TSX збережені лише у тимчасовій папці для ознайомлення.

## Перевірено

- Production-збірка з TypeScript, frontend-регресії та нові тести дозволених вкладок/жестів пройшли. Lint змінених компонентів та `git diff --check` пройшли.
- У локальному браузері на 390 px відкриваються ліве меню, праве меню, форма нового клієнта з універсального створення та глобальний пошук із результатом тестового клієнта. Форма не надсилалася.
- Заміна вкладки «Бронирования» на «Клиенты» пережила перезавантаження. Аватар і праве меню показали тестові 4 непрочитаних сповіщення.
- На 360 px один місяць поміщається: popup clientWidth/scrollWidth — 324/324 px; довгий вміст прокручується вертикально (428 px висоти, 748 px вмісту).
- Ширина документа збіглася з viewport на 360, 390 і 1440 px. Основний viewport прокрутився до scrollTop 682 та 1273 px, не змінюючи фіксований верхній/нижній бар.
- Жестові обмеження pull-to-refresh перевірені автоматичними тестами. Фізичний сенсорний жест на Android/iOS та поведінка екранної клавіатури на реальному телефоні потребують окремого приймання на пристрої; браузерна перевірка цього не замінює.

Стенд використовував окремий локальний API з фіктивними даними та забороною бізнес-записів. Production API й дані не використовувалися. Окремий запуск локального production-сервера для додаткового прев’ю відхилила автоматична перевірка без деталізованої причини; production-збірка успішна, UI-сценарії перевірені до цього у dev-стенді. Деплой і push не виконувалися.

## Уточнення компонування

Панель займає доступну ширину з відступами 8 px; вибрані вкладки заповнюють її й переносяться на наступний ряд за потреби. Висота нижнього відступу контенту слідує за фактичною висотою панелі. Закритий плюс має нейтральний вигляд. Відкриті дії — окремі пігулки над ним, без спільної картки; backdrop примусово відображається і для вкладеного діалогу, перекриваючи весь екран затемненням і blur. Поточна вкладка під цим діалогом не підсвічується.

Header правого меню компактний: аватар, ім’я, компанія та роль; профіль, сповіщення, налаштування компанії, застосунок, тема й вихід розташовані рядом. Окремий нижній footer прибрано. Посилання бронювання зліва внизу має вигляд звичайного текстового посилання. Посилання «Управление финансами» прибрано з навігації статистики.

На локальному стенді перевірено п’ять вибраних вкладок: при 390 px панель має координати 8–382 px, висоту 114 px і ширину документа 390 px; при 680 px — 8–672 px, 64 px та 680 px відповідно. Backdrop відкритого створення має 390×844 px, чорний фон з opacity .65 і blur 8 px.

Уточнення перевірені локально; після перегляду користувач дозволив commit/push для перевірки на телефоні.

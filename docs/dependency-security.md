# Оновлення залежностей

Перевірка від 27 жовтня 2026 року охоплює npm-залежності, Go-модулі та версію Go у Docker.

- Next.js та `eslint-config-next`: `16.4.3`; React і React DOM: `19.3.1`.
- Сумісні оновлення npm зафіксовані в `package-lock.json`. Типи Node відповідають виробничому Node 22 у Docker.
- Go `1.27.3` зафіксований у `backend/go.mod` і `backend/Dockerfile`; локальний Go з `GOTOOLCHAIN=auto` завантажить цю версію. GitHub Actions читає ту саму версію з `go.mod`.
- Оновлені pgx, Redis, JWT, `golang.org/x/*` та тестові Go-залежності.
- Excelize зафіксовано на `v2.11.1-0.20261026001844-a33694a7c10d` (коміт `a33694a7c10d1ef9dc947a5b6b57a3aa1e5528f0`). Стабільна версія `2.11.0` ще містить відомі проблеми обробки XLSX; обраний коміт включає виправлення. Залежність не повинна автоматично відкочуватися на `2.11.0` під час оновлення до `@latest`.
- ESLint 10, TypeScript 7 і Motion 14 залишаються окремими міграціями. Поточні основні версії оновлено в межах сумісності.

Після оновлення `npm audit` не знаходить вразливостей. `govulncheck ./...` не знаходить вразливостей у коді або імпортованих пакетах. Єдине повідомлення на рівні модулів — [GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) про непідтримуваний `golang.org/x/crypto/openpgp`: проєкт його не імпортує; використовується `bcrypt` з того самого модуля. Для OpenPGP немає виправленої версії, тому це повідомлення не усувається оновленням модуля.

## Повторна перевірка

У корені репозиторію:

```sh
npm ci
npm audit
npm test
npm run typecheck
npm run lint
npm run build
```

У `backend/`:

```sh
go mod verify
go run golang.org/x/vuln/cmd/govulncheck@latest ./...
go test ./...
go vet ./...
```

Інтеграційні тести потребують одноразових PostgreSQL і Redis. Не встановлювати тестові URL на робочу базу. Перед розгортанням діє процедура резервного копіювання та перевірки відновлення з README.
